# Speculative-execution sources outside Linux: catalogue

Scope: catalogue only. Nothing downloaded, no code written. "Verified" means a WebFetch or WebSearch hit resolved the URL during this pass. Counts are rough and were not measured. Licences marked "(knowledge)" were not checked against the source. Several GitHub listings were truncated at 1,000 files, so absence of a file name in those listings is not proof that it does not exist.

## Notes

1. **XSA is the highest-value source here.** XSA-254 onward gives roughly 20 speculative advisories, each with a patch and a named function. Xen covers V1, V2, V4, L1TF, MDS, Retbleed, SRSO, BHI and more, so it is the broadest class coverage among non-Linux sources. Start with XSA-254 (V1/V2 bounds and indirect branch), XSA-263 (V4), XSA-273 (L1TF), XSA-297 (MDS), XSA-456 (BHI). Caveat: the advisory titles are verified, but I did not read every patch to confirm its function-level labels. XSA-466 and XSA-453 are named but not analysed here.
2. **Xen `nospec.h` gives labelled V1 pairs.** Every `array_index_nospec` call site is a candidate mitigated pattern. Its pre-fix version is the vulnerable one, so `git blame` on the call sites is the extraction route.
3. **Compiler test suites are labelled but small.** LLVM SLH tests, GCC `spec-barrier-*.c`, and Go `test/codegen/spectre.go` are useful as pattern exemplars, not full gadgets. They mark what a mitigation looks like, not a leaking victim. This matches the existing memory note that c_vulns fragments lack the secret-to-transmit dataflow.
4. **Browsers (V8, WebKit, SpiderMonkey) are the best source for V1 index-masking pairs in JIT code.** Their fix commits name the mitigation, which gives a vulnerable-to-mitigated diff. The blog posts are verified, but the commit list has to come from the repos. The FreeBSD SSB and OpenBSD items are not yet confirmed and should not be counted.
5. **Microsoft `/Qspectre` docs and libsodium add little.** The docs contain no examples. libsodium is constant-time crypto with few explicit speculation fixes.
6. **Unverified or dead URLs.** FreeBSD SA-18:09.speculative does not exist; SA-18:09 is L1TF. The `webkit.org` changeset links may be dead, so use GitHub mirrors. BoringSSL returned 404 on the URL tried.
7. **Not covered in this pass.** KVM and QEMU (their Spectre and L1TF fixes are mostly in the Linux kernel and QEMU repos, which may need a separate pass), glibc, Rust (no `speculation-safe` option was checked), and MSVC blog examples.

## Recommended order

1. Xen XSAs (XSA-254, 263, 273, 297, 456), plus `nospec.h` call sites.
2. V8 and WebKit index-masking and poisoning commits.
3. LLVM SLH and Go `spectre.go` tests (pattern exemplars only).
4. Everything else, after confirmation by grep.
