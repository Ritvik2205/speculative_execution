## C. Notes for the paper

1. **Benign definition.** Production code means distribution packages (Debian, Fedora) compiled by the distributor. Academic datasets are mostly built from GitHub repos or GNU packages, which is a narrower population.
2. **Labels and ground truth.** Function boundaries come from debug info (Debian `-dbgsym`, Fedora debuginfo) or from the dataset's own function DB. State which one you used.
3. **Contamination.** Several academic sets (BinKit, Trex, Cisco) overlap with GNU packages used in gadget corpora. Check overlap against the vulnerable-gadget source list before claiming held-out status.
4. **Licences.** Record the licence of each binary, not only the repo licence. Assemblage explicitly keeps per-binary licences.
5. **Reproducibility.** Pin Debian snapshot dates and record SHA256 per binary. Reproducible-build status for Debian and Fedora was not verified here.

## D. Recommendation (2-3 most defensible benign sets)

1. **Debian amd64 + riscv64 (primary).** Official archive for both ISAs, riscv64 is an official release architecture (verified), `-dbgsym` packages give ground-truth symbols, snapshot pinning gives reproducibility. Strongest choice for "reputable, citable, production code".
2. **Fedora x86_64 + riscv64 (secondary, cross-check).** Independent distribution with RPM sources and debuginfo; provides a second-distro control for the x86 benign set. Verify riscv64 primary-arch status before claiming parity with Debian.
3. **Assemblage (x86-64 only, comparison set).** Peer-reviewed NeurIPS 2024 D&B dataset with per-binary licence tracking and large scale. Use as an external comparison benchmark, not as the primary benign set, since it is GitHub-sourced and x86-64 only.
