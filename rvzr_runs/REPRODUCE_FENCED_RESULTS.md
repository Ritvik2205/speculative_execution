# Fenced-mitigation matrix — i5-8300H (Coffee Lake)

For every recorded violation that reproduces on this box (L1TF, SPECTRE_V1,
SPECTRE_V4), build an `lfence`-hardened copy of its program and replay it with
the **same recorded inputs**. If the baseline reproduces (`violations=1`) and the
fenced copy does not (`violations=0`), the `lfence` mitigation is confirmed on
silicon by the same replay method used in `REPRODUCE_RESULTS.md`.

Generated by `oracle/revizor/scripts/reproduce_fenced_matrix.sh`; baseline counts
come from the prior reproduce matrix (`*/reproduce.log`), fenced counts from
`*/reproduce_fenced.log`; table in `reproduce_fenced_summary.tsv`.

The fenced copy inserts `lfence` at every instruction boundary (Revizor's
`fence_all` placement): `lfence` *after* each non-terminator instruction and
*before* the first terminator of each basic block (so the terminator stays last
in its BB — required by Revizor's asm parser).

## Findings

1. **`lfence` serialization is confirmed on silicon for all three reproducing
   classes** (L1TF, SPECTRE_V1, SPECTRE_V4), by the same recorded-input replay
   that established the baseline leaks — 20/20 fenced copies go silent.
2. **SPECTRE_V4 is also mitigated by `lfence` here** (14/14), across both SSBP
   masks. This is slightly stronger than expected: store-bypass speculation is
   not always stopped by a load fence, but on this box the `fence_all` placement
   closes the V4 channel on every recorded gadget.
3. The mitigation holds on exactly the gadgets that leak in `REPRODUCE_RESULTS.md`
   — i.e. the pairing is baseline-leaks / fenced-silent on the identical program
   and inputs, which is the on-silicon control T3 needs.

## Notes / caveats

- SMT was **on** for this matrix (matching the baseline reproduce matrix), so the
  baseline↔fenced comparison is apples-to-apples. MDS is absent because its
  recorded violations do not reproduce on this box at all (see
  `REPRODUCE_RESULTS.md`, MDS 0/6), so there is no baseline leak to mitigate.
- `fence_all` is a maximal placement (fence at every boundary); it confirms the
  channel *can* be closed, not that any single targeted fence suffices.
- Building the fenced program correctly required recognizing every x86 jump
  mnemonic as a basic-block terminator; see the script history for the parser
  constraint (`lfence` must never follow a terminator).
