# HW reproduction matrix — i5-8300H (Coffee Lake)

Replaying recorded Revizor violations on real hardware via
`rvzr reproduce -s base_x86.json -c reproduce.yaml -t program.asm -i input_*.bin`
(the recorded 200 inputs per dir, **not** regenerated from seed).
Generated by `oracle/revizor/scripts/reproduce_hw_matrix.sh`; raw per-dir output in
each `*/reproduce.log`, machine-readable table in `reproduce_summary.tsv`.

`violations=1` = the recorded leak re-triggered on this box (reproduce emits a
`Violations detected` HTrace table, Effective Cls 100%). `violations=0` = clean
run, inputs classified, **no** violation observed.

## Verdict by class

| class | config | dirs | reproduced | result |
|---|---|---:|---:|---|
| L1TF | baseline (SMT on) | 3 | 3/3 | reproduces reliably |
| L1TF | SMT off | 3 | 3/3 | reproduces reliably |
| SPECTRE_V1 | baseline | 3 | 3/3 | reproduces reliably |
| SPECTRE_V4 | SSBP mask `4444444` | 8 | 8/8 | reproduces reliably |
| SPECTRE_V4 | SSBP mask `5555555` | 6 | 6/6 | reproduces reliably |
| MDS | baseline (SMT on) | 3 | **0/3** | **does not reproduce** |
| MDS | SMT off | 3 | **0/3** | **does not reproduce** |

## Findings

1. **L1TF, SPECTRE_V1, SPECTRE_V4 reproduce 100%** from recorded inputs on this
   i5-8300H — the recorded violations are real, stable hardware leaks.
2. **MDS does not reproduce at all** (0/6), under either SMT setting. The recorded
   MDS violations do not re-trigger on this box with the saved inputs.
3. **SMT on vs off makes no difference** here: L1TF 3/3 both ways, MDS 0/3 both
   ways. SMT is not the gating factor for reproduction on this machine.
4. **V4 reproduces across both SSBP masks** (`4444444` and `5555555`), i.e. the V4
   leaks are not an artifact of one store-bypass mask.

## Why this run (and not minimize)

`rvzr minimize` regenerates inputs from `data_generator_seed` and cannot replay the
recorded `input_*.bin`, so it bails with "Could not reproduce the violation" on
~98% of dirs. `rvzr reproduce -i` replays the exact recorded inputs, which is why
it cleanly re-triggers the stable classes here. The MDS 0/6 is therefore a genuine
non-reproduction, not an input-regeneration artifact.

## Caveat

First two attempts at this matrix were invalid: a multi-line `sudo bash -c` pasted
into the terminal dropped the `-i <inputs>` continuation line, so `rvzr` generated
random inputs (`Inputs per test case: 100`) instead of replaying the recorded 200.
This run was done from the committed script — every dir shows `n_inputs=200`,
confirming the recorded inputs were actually replayed.
