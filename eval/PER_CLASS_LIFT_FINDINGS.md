# Per-Class Recall Lift Findings (learned/both vs hand)

## What was tested

Per-class recall lift from fusing learned encoder features with hand-crafted
features, measured on the locked 5-seed `eval/full_tost/` results (hand vs
`both` fusion mode, seeds `[42, 1, 7, 13, 21]`), using `eval/per_class_lift.py`.
For each vulnerability class present in both modes' classification reports,
the script computes the mean recall difference (`both - hand`) with a 95%
two-sample-t confidence interval, and flags the effect `significant` when
that CI excludes 0.

## The prior belief being checked

Project memory (`specdiscover-phase1-learned-features.md`) frames learned
features as complementing hand features and "mainly helping rare classes,"
naming BHI, L1TF, RETBLEED, and SPECTRE_V2 specifically as the rare classes
expected to benefit, with the majority class (BENIGN) not expected to
benefit.

## What was found

Numbers below are from `eval/per_class_lift_results.json` (`classes` section,
`other_mode: both`):

| class | hand mean | both mean | diff | 95% CI | significant |
|---|---|---|---|---|---|
| L1TF | 0.638 | 0.757 | **+0.119** | [+0.068, +0.170] | **YES** |
| SPECTRE_V2 | 0.877 | 0.758 | **-0.118** | [-0.229, -0.007] | **YES** |
| INCEPTION | 0.864 | 0.823 | -0.040 | [-0.134, +0.053] | no |
| SPECTRE_V1 | 0.995 | 0.957 | -0.038 | [-0.063, -0.013] | YES |
| MDS | 0.956 | 0.920 | -0.036 | [-0.099, +0.028] | no |
| RETBLEED | 0.923 | 0.955 | **+0.032** | [+0.012, +0.052] | **YES** |
| BRANCH_HISTORY_INJECTION | 0.919 | 0.946 | +0.027 | [-0.037, +0.091] | no |
| BENIGN | 0.996 | 0.973 | -0.023 | [-0.028, -0.017] | YES |
| SPECTRE_V4 | 0.992 | 0.987 | -0.005 | [-0.010, +0.001] | no |
| SPECTRE_RSB | 0.400 | 0.400 | 0.000 | [-0.799, +0.799] | no (n=1 support, uninformative) |

Of the four rare classes named in the prior belief:

- **L1TF** (test-set support 37, the rarest real class): real, statistically
  significant positive lift (+0.119, CI excludes 0). Matches the claim, and
  is the largest positive effect in the table.
- **RETBLEED** (support 75): smaller but real, statistically significant
  positive lift (+0.032). Matches the claim.
- **BHI** (support 67): positive point estimate (+0.027) in the same
  direction as the claim, but the CI straddles 0 — not distinguishable from
  noise at this seed count. Directionally consistent, not confirmed.
- **SPECTRE_V2** (support 154 — the *least* rare of the four named classes):
  statistically significant recall **loss** (-0.118, CI [-0.229, -0.007]).
  This is a direct contradiction of the prior belief for this specific
  class, and it is the second-largest-magnitude effect in the whole table
  (positive or negative) — not a marginal footnote.

Two classes not named in the prior belief also show significant losses:
BENIGN (majority class, -0.023) and SPECTRE_V1 (-0.038, and by test-set
support one of the rarer classes — 42 examples, rarer than BHI or RETBLEED).
So even reading "rare classes benefit" as a support-based rule rather than
the fixed four-class list, rarity alone does not predict which classes
benefit from fusion.

## Bottom line

The "learned features help rare classes" claim is a **partial match, not a
confirmed wholesale finding**. It holds for L1TF and RETBLEED (real,
significant, positive lift). It is directionally consistent but statistically
unconfirmed for BHI. And it is **reversed** for SPECTRE_V2, one of the four
classes the claim specifically names — fusion costs ~12 points of recall on
SPECTRE_V2 relative to hand-only features, a significant effect, not noise.
Any process or gate built on "fusion helps rare classes, ship it" needs to
account for the SPECTRE_V2 regression rather than wave it away.
